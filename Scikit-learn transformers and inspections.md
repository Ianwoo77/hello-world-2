##### Categorical Attribute

Cuz the possibilities of these values are limited and represent a classification, this feature is called *categorical attribute*.

The need for digital transformation -- Most machine learning alg work primarily based on the mathmatical formulas. They cannot directly underrstand strings like *INLAND* -- there fore, need to `map`these text labels to numbers.

- `OrdinalEncoder`-- This is a class of tools provided by scikit-learn specifically designed to convert category features from text to integers.

##### Important Considerations -- potential issues

Whlile `OrdinalEncoder`successfully converts text to number, it has a drawback in some scenarios -- 

- Misleading order -- The numbers generated by `OrdinalEncoder`are order of size.
- Alg misconceptions -- ML acn mistakenly belive that two categories with similar values are more similar than those with distant values.

Fore, if 0 stands for good and 4 starts for very poor, then 0 and 1 are indeed closer and 0 and 4. So if there is no obvious order relationship between categories, it is generally recommended to use One-hot encoding, i.e. The `OneHotEncoders`class in `Scikit-learn`, instead of `OrdinalEncoder`.

One issue with this representation is that ML algs will assume that two nearby values are more than two distant values. To fix this, a common solution is to create one binary attribute per category -- one equal 1 when category `<1H OCEAN`and 0 otherwise, another equal 1 when the category is INLAND.

| **Encoding Type**    | **Description**                               | **Best Use Case**                        |
| -------------------- | --------------------------------------------- | ---------------------------------------- |
| **Ordinal Encoding** | Maps categories to integers (0, 1, 2...)      | Ordered data (e.g., Ratings, Sizes)      |
| **One-Hot Encoding** | Creates a new binary column for each category | Unordered data (e.g., Locations, Colors) |

```python
from sklearn.preprocessing import OneHotEncoder
cat_encoder = OneHotEncoder()
housing_cat_1hot = cat_encoder.fit_transform(housing_cat)
```

A sparse matrix is a very efficient representation of matrices that contain mostly zeros -- indeed, internally it only stores the nonzero values and their positions. And when a categorical attribute has hundreds or thousands of categories, one-hot encoding it results in a vary large matrix full of 0s except for a single 1 per row.

Alternatively, you can set `sparse=False`when creating the `OneHotEncoder`, in which casee the `transform()`method will return a regular NumPy`array directly.

As mentioned in the previous section, representing categories with 0 1 and 2 can lead the alg into thinking that there is a size or distance relationship between categories -- to dispel this misunderstanding, we need an expression of equality.

##### What is Solo thermal coding -- 

- Principle -- create a new binary attribute for each possible category only 0 and 1 values
- operation -- If the sample belongs to category A, the column that represtns A is 1 (hot)
- other columns representing categories are 0 (cold).
- These newly generted columns are often referred to as Dummy Attributes/Variables.

#### Key tech points - Sparse Matrix 

This the most technical part of this text that explains how Scikit-Learn handles memory issues -- 

- Default output format -- When run the `fit_transform()`, will find that the output `housing_cat_1hot`is not a normal Numarray, but a Scipy sparse matrix.
- Why use a sparse matrix -- 
  - Question -- say your feature is *city* -- there may be 1000 different cities -- after thermal coding, there are 1000 columns per sample, but in each row, only 1 position is 1, and 
  - Waste -- If stored in a normal matrix, these 999 zeros will take up a lot of memory and completely wasted.
  - Solution -- The sparse matrix only stores the position and value of non-zero elements. It internally records information like there is 1 in 3 and column 5. Instead of storing thousands of zeros.

Data conversion - `toarray()`-- Call the `.toarray()`.

### Fuzzing a riksy function

Let’s take a more complicated and exmaple, to set the scene, a word or two about `string bytes, runes`and characters in Go -- 

```go
func FuzzFirstRune(f *testing.F) {
	f.Add("Hello")
	f.Add("World")
	f.Fuzz(func(t *testing.T, s string) {
		got := runes.FirstRune(s)
		want, _ := utf8.DecodeRuneInString(s)
        // suppose the fuzzer is constant utf8.RuneError, get the result, then this particular input
        // is i
		if want == utf8.RuneError {
			t.Skip()
		}
		if want != got {
			t.Errorf("given %q (0x%[1]x): want '%c' (0x%[2]x)",
				s, want)
			t.Errorf("got '%c' (0x%[1]x)", got)
		}
	})
}

func FirstRune(s string) rune {
	for _, r := range s {
		return r
	}
	return utf8.RuneError
}
```
